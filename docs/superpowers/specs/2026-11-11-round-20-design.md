## §1 Tag expressions: model, wire, evaluation (lane A)

**Why.** Lumen has two searches. The typed sentence (`/search?q=`, `query_expr.rs`) knows
`or / and / not`. The tag chips of every grid page (`tag_search.rs`, `TagSearchField`, `TagBar`)
combine by a fixed rule: values of one field are OR, everything else AND (`to_query`,
`tag_search.rs:129`). So *Live Photos* and *HDR* can only ever be "or", and typing `live and hdr`
into the tag field becomes one text tag that the sentence parser cannot read, because it does not
know kinds. **J:** one token row is the single truth: tag chips, clickable operators, groups.

### Model (new file `photos-core/src/tag_expr.rs`)
```rust
pub enum Join { And, Or }                       // wire: "and" | "or"
pub enum TagItem {                              // #[serde(tag = "type", rename_all = "camelCase")]
    Tag   { not: bool, tag: SearchTag },        // `not` defaults false and is omitted when false
    Group { not: bool, seq: TagSeq },
}
pub struct TagSeq { pub items: Vec<TagItem>, pub joins: Vec<Join> }
```
- `joins[i]` sits between `items[i]` and `items[i + 1]`, so `joins.len() == items.len() - 1`.
  A sequence is always well formed: there is no dangling operator to repair by hand.
- Reading a sequence: `not` binds tightest, then `and`, then `or` (Round 19's precedence).
  `A or B and C` is `A or (B and C)`. A `Group` is a bracketed sub-sequence.
- All three types derive `Debug, Clone, PartialEq, Eq, Hash, Serialize, Deserialize, TS` with
  `#[ts(export)]`, camelCase. TS sees `not?: boolean`.
- Limits: at most 24 tags, groups at most 4 deep.

### `TagSeq` functions (all pure, all unit-tested first)
- `repaired(&self) -> TagSeq` — the one normal form. In this order, until nothing changes:
  1. `joins` cut or padded with `And` to `items.len() - 1`.
  2. An empty group is dropped (with one neighbouring join: the one before it, else the one after).
  3. A one-item group becomes that item; its `not` is the group's `not` XOR the item's.
  4. A group that is **not** negated is spliced into its parent when that cannot change the
     meaning: its joins are all `And`; **or** both joins beside it in the parent are `Or` or absent.
  5. Past the limits: only the first 24 tags are kept; a group deeper than 4 is flattened into its
     parent with its joins.
- `to_expr(&self, leaf: &mut impl FnMut(&SearchTag) -> QueryExpr) -> Option<QueryExpr>` — `None`
  when empty. Split `items` at every `Or` join into runs; a run of one item is that item's
  expression, a longer run is `QueryExpr::And`; one run is itself, several are `QueryExpr::Or`.
  An item: `Tag` → `leaf(tag)`, `Group` → `seq.to_expr(leaf)`, wrapped in `QueryExpr::Not` when
  `not`. (`QueryExpr` is `query_expr.rs:33`; its `sql()` already combines leaves.)
- `core_leaf(tag) -> QueryExpr` = `QueryExpr::Leaf(Box::new(tag_search::to_query(&[tag.clone()])))`.
- `as_plain(&self) -> Option<Vec<SearchTag>>` — `Some` only when the sequence says exactly what
  the old flat list said, so the old path can run it unchanged:
  no `not` anywhere; every top-level join is `And`; every top-level item is a `Tag`, or a `Group`
  whose joins are all `Or` and whose items are all `Tag`s with the **same** `OrKey::Field` key;
  and no key (of either kind) appears in two top-level items. (`Live and HDR` therefore is **not**
  plain: the old path would read it as "or".)
- `or_key(&TagValue) -> Option<OrKey>` — how `to_query` (`tag_search.rs:129`) treats two tags of
  the variant. This table is the contract; derive nothing else from `to_query`:

  | Variant | Key | Old path with two of them |
  |---|---|---|
  | person, pet, album, collection, scene, favorites, hasText, noText, photoText, text, lumen | `None` | AND (each must hold) |
  | media, kind, place, extension, shape, rating, months | `Field("<variant>")` | OR (rating: the lower; months: union) |
  | dates | `Field("dates")` for taken or no field, else `Field("dates:<field>")` | OR |
  | exif | `Field("exif:<field>")` | OR |
  | range | `Field("range:<measure>")` | OR |
  | flag, location | `Single("<variant>")` | the last one wins |

  A `Single` key may appear once at the top level and never inside an `or` group of a plain
  sequence (two flags are never plain; the tree then reads them as written).
- `leaves(&self) -> Vec<(&SearchTag, bool)>` — reading order, `true` when the tag counts for
  photos (under an even number of `not`s).

### Wire and evaluation
- `AssetQuery` (`query.rs:17`) gains `pub tag_expr: Option<TagSeq>`
  (`#[serde(default, skip_serializing_if = "Option::is_none")]`, TS `tagExpr?:`). Absent means
  today's behaviour and today's code path. `search_tags` stays for queries saved before this.
- Core, `AssetQuery::expanded()` (`query.rs:545`), first thing: with `tag_expr` present, take its
  `repaired()` form `s`; if `s.as_plain()` is `Some(tags)` → continue exactly as if those tags
  had been appended to `search_tags`; else → `expr = and_of(self.expr, s.to_expr(core_leaf))`
  (one `QueryExpr::And` of the two when both exist). Either way `tag_expr` is `None` in the result.
  `sql_parts_with` (`query.rs:602`) takes its early `expanded()` return for `tag_expr` too.
  **This is the one choke point:** every count, list, layout, map and smart album builds its SQL
  through `sql_parts_with`, so all of them read a `tag_expr` the same way with no other change
  (`search_tags` has no other reader: Grep confirms `query.rs` and `search.rs:75` only).
  As in Round 19, `expr` is one more WHERE clause ANDed with the query's other fields (album
  scope, device, the page's filters), so a tag sequence narrows a page exactly as tags did.
  A `Some` sequence with no items counts as absent (`is_empty`, `expanded`).
- Saved smart albums store this same `AssetQuery` JSON, so they need nothing else. **Call:** no
  migration and no downgrade promise — a Lumen from before this round would ignore `tagExpr` in
  an album saved by this one (alpha; one user).
- `asks_for_raw` (`query.rs:554`) is also true when a leaf of `expr` that counts for photos asks
  for RAW. Add an immutable walk beside `leaves_mut` (`query_expr.rs:69`).
- App, `search::understood` (`src-tauri/src/search.rs:73`), before its `search_tags` branch: a
  query whose `tag_expr` is not plain is turned into `expr` here, with a smarter leaf than core's:
  a `TagValue::Text { text }` tag is read the way typed text is — `parse_expression(state, text)`
  gives its tree; else `parse(state, text)` gives one leaf (`query_parse::merge` of a text-only
  query with `parsed.query`, as lines 86–93 do). Every other tag uses `core_leaf`. The query's own
  `text`, when set, becomes one more text leaf ANDed in, and `text` is cleared. Then the existing
  `with_expression` path runs (`fill_terms` gives every leaf its meaning hits; *Best match* works).
  A plain `tag_expr` just falls through to the existing `search_tags` branch via `expanded()`.

## §2 Typed sentences become tags (lane A)

**J:** "make it work with everything… a tokenizer which separates each one into its parts."
`live and hdr not screenshot` typed in the tag field becomes
`[Live Photos] and [HDR] and not [Screenshot]`: every part a real tag.

### Reader (new file `photos-core/src/tag_sentence.rs`)
```rust
pub struct SentenceReading {           // ts-rs export, camelCase
    pub lead: Option<Join>,            // "or hdr": how the sentence joins what is already chosen
    pub seq: TagSeq,                   // repaired; may be empty while only an operator is typed
    pub term: String,                  // the last term as typed, "" when the text ends in an operator
}
pub fn read(facets: &Facets, input: &str, today: NaiveDate, order: DateOrder) -> Option<SentenceReading>
```
- **Cutting.** Reuse Round 19's lexer and descent: make `Lex`, `Tok`, `Node`, `operators` and
  `Descent` in `query_expr.rs` (`:157`–`:414`) `pub(crate)`, and add
  `pub(crate) fn parse_nodes(text: &str) -> Option<Node>` there (what `parse_expr` does before it
  reads terms: `operators`, the any-operator check, `Descent::expr`, the limits). No behaviour of
  `parse_expr` changes; its tests stay green.
- **Lead and tail**, handled in `read` before `parse_nodes`: a first word `and` / `or` followed by
  more text is the `lead` and is cut off; trailing `and` / `or` / `not` words are cut off (the
  person is still typing) and make `term` empty. `not x` alone is no lead: it is `Not(x)`.
- `read` returns `None` when there is no lead, no tail and `parse_nodes` finds no operator: the
  text is one plain term and the field behaves as today.
- **Tree to sequence.** `Node::Term(s, e)` → `Tag` via `resolve` below. `Not(n)` → the item of
  `n` with `not: true` (a `Group` when `n` is `And` / `Or`). `And(v)` → items joined by `And`, an
  `Or` child becoming a `Group`. `Or(v)` → children joined by `Or`; an `And` child is spliced in
  with its own `And` joins (no group needed, `and` binds tighter). Finish with `repaired()`.
- **`resolve(term) -> SearchTag`** — the heart of "works with everything":
  1. A term that is one quoted phrase → `Text { text: <inside the quotes> }`.
  2. Ask `tag_search::candidates(facets, term, today, order)` (below) and take the first
     candidate when it is **sure**.
  3. Otherwise `Text { text: term }`, label = the term. At query time §1's app leaf reads it as a
     sentence (`anna in paris`, `beach at sunset`), so nothing typed is ever lost.
- **`candidates`** — refactor `suggest` (`tag_search.rs:927`) so its body builds
  `Vec<Candidate { suggestion: TagSuggestion, sure: bool }>` and `suggest` maps it back
  (same output, its tests untouched). `sure` is true for: a tag made by a reader of the whole
  input (`photo_text_prefix`, `read_date`, `date_field_prefix` + `read_date_expr`,
  `read_date_expr`, `read_comparison`); a facet entry whose label, folded, equals the typed words
  (`whole`); a facet entry with total score 0 (every typed word is a whole word of the label) that
  is the only such entry, or the only `fixed` one among them. Never the trailing `Text` entry.
  Everything needed is already there: `Entry.fixed` (`tag_search.rs:364`) and the scored tuple
  `(total, !whole, count, entry)` inside `suggest` (`:963`–`:978`).
  So `live` → *Live Photos*, `hdr` → *HDR*, `2026` → *2026*, `anna` → the one Anna; two Annas →
  text `anna`, which the sentence parser then reads with its own alternatives.

### Command

## §3 The token row: clickable `and` / `or` / `not`, groups (lane A)

**J:** click an operator to change it (`and | or | and not | or not`); a bracket is a grouped pill.
```
[ 2026 ] and ( [ Live Photos ] or [ HDR ] ) and not [ Screenshot ]   Clear
          ^ quiet, muted          ^ stronger      ^ stronger
```

### `src/lib/search-expr.ts` (pure; the only code that edits a sequence; unit-tested)
```ts
export type Path = number[];                       // item indices down through nested groups
export const EMPTY_SEQ: TagSeq = { items: [], joins: [] };
export function repair(seq: TagSeq): TagSeq;       // §1's rules, held by the golden file
export function orKey(value: TagValue): string | null;        // §1's table: "field:kind", "single:flag", null
export function fromLegacy(tags: SearchTag[]): TagSeq;
export function leaves(seq: TagSeq): { tag: SearchTag; not: boolean; path: Path }[];
export function flatTags(seq: TagSeq): SearchTag[];           // leaves' tags, reading order
export function plainTags(seq: TagSeq): SearchTag[] | null;   // §1's as_plain, same golden cases
export function addTag(seq: TagSeq, tag: SearchTag, how?: { join: Join; not: boolean }): TagSeq;
export function appendSeq(seq: TagSeq, more: TagSeq, lead: Join | null): TagSeq;
export function removeAt(seq: TagSeq, path: Path): TagSeq;
export function removeLast(seq: TagSeq): TagSeq;
export function setJoin(seq: TagSeq, group: Path, index: number, join: Join, not: boolean): TagSeq;
export function toggleNot(seq: TagSeq, path: Path): TagSeq;
export function groupPair(seq: TagSeq, group: Path, index: number): TagSeq;  // items index, index+1
export function ungroup(seq: TagSeq, path: Path): TagSeq;
export function describe(seq: TagSeq): string;     // "2026 and (Live Photos or HDR), not Screenshot"
```
Every mutation returns a repaired sequence. `group` is the path of the sequence being edited
(`[]` is the top). `setJoin` sets `joins[index]` and the `not` of item `index + 1`.

**`addTag` without `how`** (a tag picked from the list; keeps Round 7's feel):
1. Already among the leaves (`sameTag`) → unchanged.
2. Let `g = orKey(tag.value)` when it is a `field:` key, else none (a `single:` key and `null`
   go to rule 4). `orKey` replaces `orGroup` (`lib/search-tags.ts:53`), which is removed with
   `clusterTags`. If the whole top level is non-negated tags of group `g` joined only by `or` →
   append `or tag`.
3. Else if a top-level item is a non-negated tag of group `g`, or an all-`or` group of such tags →
   the tag joins it with `or` (the single tag becomes a group; a lone top-level tag just gets
   `or tag` beside it).
4. Else append with `and`; if the top level has any `or` join, the existing top level is wrapped
   in one group first, so the result reads `(everything so far) and tag`.

**`addTag` with `how` / `appendSeq`** (typed `or hdr`, `not screenshot`, a whole sentence): `and`
wraps the existing top level first when it has an `or` join (rule 4); `or` appends as is. A
sentence with several items is appended as one group unless its joins are all the lead's join.

`fromLegacy`: cluster by `field:` key in first-seen order; a cluster of several tags is an `or`
group; clusters join with `and`; of several tags with one `single:` key only the last is kept
(what the old path did). This reads every old URL and every saved smart album, and its result is
always plain.

### The row (`components/tag-search/token-row.tsx`, new; `TagBar` in `gui.tsx:430` becomes a thin
wrapper that renders it, so its users do not change)
- Renders a sequence recursively: for item `i`: a **join button** when `i > 0`; a lone **not
  button** when `i == 0` and the item is negated; then the tag chip or a **group pill** holding
  the nested sequence. *Clear* stays last. `readOnly` draws the same row with no buttons (used by
  the field's sentence preview, §3 below).
- **Join button** (`tag-bar__join`): label `and`, `or`, `and not`, `or not`. Click, Enter or
  Space opens a Mantine `Menu` (`withinPortal`): the four choices with a check on the current
  one; divider; *Group these two* (or, when the button is inside a group, *Ungroup*). `aria-label`
  "`and` — change how these combine".
- **Tag chip**: as today (icon, label, ×). Clicking the label opens a menu: *Exclude* / *Include*,
  *Remove*. A negated chip is drawn with the `not` in the join button before it, never inside it.
- **Group pill** (`tag-bar__group-pill`): a rounded outline with a faint surface, its content the
  nested row. A negated group has `not` before it.
- **Precedence you can see:** `and` is quiet (muted text, no surface, `--space-1` gaps); `or` and
  anything with `not` is stronger (primary text, the chip surface, `--space-2` gaps). And-runs
  therefore read as clusters without brackets.
- Motion as today (`SPRING`, layout, presence); keys from `tagKey`, so a chip keeps identity when
  operators around it change. Tokens only; the pill and join styles go in
  `tag-search/styles.scss`; any new colour is a token appended to `globals.scss`.

- Without a reading: exactly today's behaviour (`store.add(tag)`).
- The dropdown's hint line gains `and · or · not between tags`. The empty box's *Try* list gains
  one row that fills the input (does not commit): `live or hdr not screenshot`.
- New optional prop `portal`: the dropdown renders in a portal anchored to the field (Mantine
  `Popover` with `withinPortal`, `width="target"`), so a modal cannot clip it (§4). The page
  header keeps the inline dropdown.
